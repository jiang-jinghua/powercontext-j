# Qoder Sites 发布步骤（本项目实操）

> 题目硬性要求：项目网站必须通过 Qoder Sites 发布，且**未登录也能打开**。
> 本项目是纯静态站点（根目录 `index.html` + `css/` + `js/`），无需构建步骤，可直接打包发布。

## 前置检查

- Qoder 桌面端 v0.3.3 以上 / CLI v1.1.54 以上（版本过低时输入 `/sites` 无反应，先升级）
- 已登录 Qoder 账号

## 步骤

### 1. 打开项目工作区

在 Qoder 中打开本项目目录（`index.html` 所在目录），确保左侧文件树能看到
`index.html`、`css/style.css`、`js/store.js`、`js/adapters.js`、`js/app.js`。

### 2. 进入 Sites

两种入口任选其一，产出一致：

- **侧边栏入口**：左侧边栏点「站点 / Sites」→ 点「添加站点 Add site」，会新建一个任务，输入框自动带 `@sites` 标识
- **命令入口**：新建任务，在输入框输入 `/sites`

### 3. 发送发布指令（关键：要求"发布已有项目"而不是重新生成页面）

在输入框粘贴下面这段，把 `<项目绝对路径>` 换成你的实际路径：

```
@sites 我这里已经有一个完成的项目，请不要重新设计页面，直接把它打包发布为站点。
项目路径：<项目绝对路径>
入口文件：index.html（纯静态，无构建步骤，CSS 在 css/，JS 在 js/）
要求：
1. 保持现有页面内容与交互完全不变，只做打包与发布
2. 站点默认以「内置演示模式」运行，打开即可操作，不需要任何账号或密钥
3. 生成预览后先不要发布，等我确认
```

> 说明：Sites 的 `sites-building` 能力支持"从已有项目构建并打包发布"。如果不加"不要重新设计"这句，
> Qoder 可能按模板重新生成一套页面，导致你的项目内容被替换。

### 4. 预览自检

生成后点击回复里的 website artifact，右侧 Sites 面板打开预览。逐项点一遍：

- [ ] 首页「今日复习」显示卡片，点「显示答案」→ 出现三键评分，点一个能进入下一张
- [ ] 「知识库」页显示 8 条示例知识点
- [ ] 「智能搜索」输入 `TCP 拥塞` 能出结果
- [ ] 「上下文召回」输入 `我之前对 TCP 复习做过什么决定？` 有返回（演示模式）
- [ ] 「调用日志」页有记录，导出按钮可下载 JSON
- [ ] 手机尺寸下布局不塌（可选）

有问题就在同一任务里用自然语言让它改，例如"知识库卡片间距再大一点，其他不要动"。

### 5. 发布

预览确认后，点 Sites 面板右上角「发布」，等待状态从"预览/草稿"变为"已发布"。

### 6. 改权限为「任何人可访问」（**最容易漏的一步**）

新站点默认是 **仅自己可访问**——此时别人拿到链接也打不开，直接不满足题目要求。

发布详情里把访问权限改为 **任何人都可访问 / Public**，需要二次确认，确认即可。

### 7. 拿到网址并验证

发布详情里复制正式网址，然后做三个验证：

- [ ] **隐身窗口/未登录浏览器**打开该网址，页面正常显示且功能可用
- [ ] 手机流量（不同网络）打开一次，确认非本地依赖
- [ ] 把网址发给一位没登录 Qoder 的同学，请对方打开并反馈

验证通过后，把这个网址填入提交表单的「作品链接」。

### 8. 后续修改怎么办

改完代码在同一任务里重新发布即可，**网址不变**，评审刷新就能看到新版。
但每次重新发布后 `git push` 的 commit id 会变——提交表单里的 Commit id 记得同步更新为最终版本。

## 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 输入 `/sites` 没反应 | 客户端版本过低，先升级到 v0.3.3 / CLI v1.1.54 以上 |
| 发布后别人打不开 | 访问权限仍是"仅自己可访问"，改成"任何人都可访问" |
| 页面被改成了模板样式 | 指令里没强调"不要重新设计"，补一句让它恢复原项目文件 |
| 预览里搜索/召回报错 | 正常。演示模式下不会报错；若你切到了"真实接入模式"，浏览器访问不到你本机的代理与 PowerContext Server，属于预期行为，切回演示模式即可 |
| 发布后数据不见了 | 站点数据存在浏览器 localStorage，换设备/换浏览器是空的，属正常；不影响演示 |
