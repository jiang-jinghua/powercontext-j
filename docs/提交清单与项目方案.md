## 二、项目方案（为什么这么做 → 对应评分维度）

**选题：学习助手（间隔重复复习工具）**

| 评分维度 | 本项目的应对 |
|----------|--------------|
| 应用价值 | 复习凭感觉、笔记找不到是学习/科研的真实高频痛点；间隔重复是被验证过的方法 |
| 使用效果 | 统计条（复习次数/掌握数）+ 邀请真实同学使用一周的反馈数据，可量化 |
| 完成度与体验 | 单页应用，六大功能闭环：复习/知识库/搜索/召回/配置/日志，评委打开即用 |
| 技术难度 | 双组件接入（seekdb 全文检索 + PowerContext 三端点闭环），适配层设计支持 mock/real 双模式 |
| Qoder 开发体验 | 留痕于 Qoder 开发记录；本项目由 Qoder 主要开发 |
| 工程素质 | 零依赖、目录清晰、API 规格与官方文档逐字对齐、调用全程留痕可验证 |

**关键设计决策**

1. **纯静态 + 适配层**：Qoder Sites 托管静态站，评委未登录可用演示模式；真实接入模式经本地代理调用官方 API，两种模式同接口、可随时切换。
2. **mock 如实标注**：演示模式下 seekdb/PowerContext 的模拟实现全部带 `(mock)` 标记并写入日志，不冒充真实调用——诚实性本身就是工程素质的体现。
3. **PowerContext 三端点闭环**：Source（过程证据）→ Memory（掌握决策）→ PreparedContext（按需召回），完整覆盖官方"采集-沉淀-召回"叙事。
4. **验证即产品**：调用日志页是产品功能的一部分，同时直接生成提交材料"验证说明"所需的运行记录。

## 三、完成路径（你还需要做的事）

1. **在 Qoder 中开发**（硬性要求）：把本目录导入 Qoder，用 Qoder 完成/迭代功能、记录会话——本项目代码已就绪，你可以让 Qoder 复查、重构、加功能（如向量语义检索），每一步都留痕
2. `git init` + 推送公开仓库，添加 LICENSE
3. Qoder Sites 发布网站（公开访问）
4. 按接入指引创建 seekdb/PowerContext 凭据，跑通 docs/验证说明.md 的 6 个用例，补齐截图
5. 邀请同学真实使用，填使用效果材料
6. 按本清单逐项核对后提交
