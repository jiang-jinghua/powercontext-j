## 1. 跨轮记忆与互动状态的实现（Dify 会话变量）

- 会话变量 `state_json`（string）：对局状态 JSON——`round / price / mood / tactics / intel / status / history`；
- 会话变量 `panel`（string）：人类可读的局面面板；
- 每轮由代码节点「结算台」产出，经「变量赋值」（assigner，operation=over-write）写回；下一轮：
  - `panel` 注入「摊主大脑」的提示词（角色据此接梗）；
  - `state_json` 传回「结算台」做确定性结算。
- 选择两个字符串变量而非 object/array 的原因：跨 Dify 版本的 DSL 兼容性最好，assigner 仅用最基础的 over-write 操作。
- **验证**：docs/03 用例 B 的面板衰减文案、`evidence/transcript-settle-sim.md` 中逐轮状态 JSON。

## 附录 A · PowerContext 可选增强配方（跨会话"老王印象"）

Dify 会话变量只能覆盖单次会话。若希望老王"隔天还认得你、记得你上次砍到几块"，可接入 PowerContext（OceanBase 开源的上下文服务，HTTP API / MCP 均可）：

1. 安装并启动本地 Server（PowerContext ≥ 1.5.0，Python 3.11+）：

   ```bash
   uv tool install --force "powercontext[cli,server]==1.5.0"
   powercontext server run          # 默认监听 http://127.0.0.1:8000，鉴权默认关闭
   ```

2. 建议用 `POWERCONTEXT_SERVER_DATABASE_KIND=seekdb` 让 PowerContext 与 Dify 共用同一 seekdb 实例，整个作品只有一份数据底座；

3. 建一个专用 Scope（`POST /v1/scopes` 或 CLI `create_scope`），语义："早市风云 · 玩家画像"，拿到 `scope_id`；

4. 预置一条老王的初始记忆（实测可跑通的最小写入）：

   ```bash
   curl --fail -X POST http://127.0.0.1:8000/v1/memory/remember \
        -H 'Content-Type: application/json' \
        -d '{"scope_id":"<scope_id>","kind":"decision","text":"老王记性差但脸熟：谁要是哪天砍到过 8 块以下，下次他嘴上不说，价签会松一点。"}'
   ```

5. 在 Dify 画布上加两个 **HTTP 请求** 节点（本作品主 DSL 未包含，保持零外部依赖）：
   - 「记忆召回」（LLM 前）：`POST http://127.0.0.1:8000/v1/memory/search`，body `{"scope_id":"<scope_id>","query":"{{#sys.query#}}","limit":3}`，输出 JSON 摘要拼进摊主大脑的提示词；
   - 「印象写回」（结算台后）：`POST http://127.0.0.1:8000/v1/memory/remember`，body 用结算台的 `status/price/tactics` 组装一句"玩家画像"文本。
6. PowerContext 若未启动，读节点会失败——建议把「记忆召回」放在 try 分支或为其配置默认空值，保证主玩法不受影响。

> 说明：以上为接入路径与实测端点（`/v1/memory/remember`、`/v1/memory/search`、`/health/live`、`/health/ready`），因本作品主线不依赖 PowerContext，未在主 DSL 中启用；按此配方启用后，请按 docs/03 §4 补充实机证据。
