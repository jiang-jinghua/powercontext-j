# 03 · 验证样例与运行证据（对应提交材料 4.3）

## 1. 证据分两层：先确定性、再实机

本作品由"LLM 表演 + 代码结算"组成，验证也分两层，两层都能独立复现：

| 层 | 覆盖内容 | 复现方式 | 状态 |
|---|---|---|---|
| 第一层：结算内核（代码节点） | 跨轮状态、招式衰减、情绪、情报加成、四种结局、异常兜底、自动开新局 | `python tests/test_settle.py`（22 项断言）与 `python tests/simulate.py`（剧本回放生成完整 transcript） | ✅ 已在本机执行，输出见 `evidence/test-settle-output.txt` 与 `evidence/transcript-settle-sim.md` |
| 第二层：完整应用（LLM + seekdb 检索） | 台词质量、检索命中、端到端对话 | 在 Dify 实机按 docs/02 部署后按下方用例对打 | ⏳ 需实机执行，按 §4 采集证据 |

> 诚实说明：本提交包在编写环境中未启动 Dify 实例（无 Docker/外网），因此第二层证据需要在评审或复现者的实例上采集。
> 第一层的两条命令任何安装了 Python 3 的机器都能立刻复跑，与 Dify 无关——因为 DSL 代码节点的内容就是从 `build/settle_code.py` 注入的，两者同源。

## 2. 实机验证用例（第二层）

**前置**：按 docs/02 完成部署、知识库导入、DSL 导入与模型/数据集选择，发布为 WebApp，新开会话。

### 用例 A · 首轮试探 + 行话挑刺（验证：RAG 检索命中 → 数值响应）

| 步骤 | 玩家输入 | 预期行为 |
|---|---|---|
| A1 | `老板，这黄瓜咋卖？能便宜点不？` | 老王报出 12 元/斤；面板显示 12.0、第 1/6 轮、招式"试探行情×1" |
| A2 | `你看看你这瓜把都黄了，还 12 块？` | 知识检索命中《黑话与挑菜》；老王被戳到会护短（知识库《老王档案》），价签小降；招式统计出现"挑刺×1" |
| A3 | `李姐那边才 9 块 5，你这 12 块是金子做的？` | 命中《邻摊报价》；老王念叨李姐（人设），让价幅度明显大于 A2；面板出现"对比邻摊×1" |

**观察点**：同一句砍价，说不出依据（A1）与说出具体依据（A3）的让价差异 ≥ 1 元；知识库文档被实际引用（运行详情中检索节点的召回内容可见）。

### 用例 B · 招式衰减（验证：跨轮状态被"记住"）

| 步骤 | 玩家输入 | 预期行为 |
|---|---|---|
| B1 | `不买了，我走了啊。` | 老王挽留，让价最大 |
| B2 | `真走了啊。` | 面板提示"「走人威胁」是第 2 次用了，这招效果只剩 ×0.60" |
| B3 | `再不便宜我可真走了。` | 效果 ×0.25，老王开始不耐烦，情绪明显下降 |
| B4 | `……你这没法聊了。` | 情绪 < 20 → 掀摊结局：`💥 谈崩了` + 隐藏成就"🥊 嘴强王者" |

**观察点**：B2/B3 的面板衰减文案；B4 结局卡。这三点在 `evidence/transcript-settle-sim.md` 剧本 B 中有逐轮实录（同一结算内核）。

### 用例 C · 情报路线速胜（验证：知识库是核心玩法）

| 步骤 | 玩家输入 | 预期行为 |
|---|---|---|
| C1 | `听说你们进货 7 块 2，8 块你都不亏吧？` | 检索命中《今日特价与暗号》中的进货价；老王"被说中底牌"，面板"情报"栏变为"已套出进货价（每轮多让 0.15 元）"，且当轮有一次性冲击让价 |
| C2 | `那就 8 块，两斤，别让我等。` | 数轮内价格到达 ≤ 8.0，`🎉 成交` + 成就"🏅 情报王"；全程 ≤ 3 轮则另得"⚡ 一刀见血" |

### 用例 D · 异常兜底（验证：工程质量）

| 步骤 | 操作 | 预期行为 |
|---|---|---|
| D1 | 输入一句故意让 LLM 跑偏的话（如纯数字 `1234567890`） | 应用不报错：结算台对非 JSON 输出降级处理（原文本当台词 + 按"试探行情"结算） |
| D2 | 结局达成后再发一句 `再来一把` | 自动开新局：面板回到 12.0 元/斤、第 1 轮 |
| D3 | 断开知识库（临时把检索节点数据集清空）运行 | 情报栏显示"无"，对局仍可进行（检索缺失不致命） |

## 3. 第一层证据（已生成）

```bash
python tests/test_settle.py     # 22 项断言，输出重定向自实跑：evidence/test-settle-output.txt
python tests/simulate.py        # 3 个剧本 × 逐轮 transcript：evidence/transcript-settle-sim.md
```

- 剧本 A（情报开局）→ 4 轮成交，价 7.8 元/斤，成就"情报王"；
- 剧本 B（重复威胁）→ 4 轮掀摊，情绪 14/100，隐藏成就"嘴强王者"；
- 剧本 C（只攒情绪不砍价）→ 6 轮触发收摊友情价，8.2 元/斤成交（离目标差 0.2 元，成就里如实标注）。

transcript 中每轮附有写回会话变量的状态 JSON，与 DSL 的 `state_json` 字段逐字段一致。

## 4. 证据采集清单（实机执行时按此归档）

1. **对话截图**：用例 A~D 每步一张（含老王台词 + 状态面板）；
2. **Dify 运行详情**：任一轮的"运行详情"页截图，展示 6 个节点的执行链与耗时、知识检索召回的具体文档片段、LLM 的 JSON 输出；
3. **会话变量**：运行详情中 `conversation.state_json` / `conversation.panel` 的最终值截图；
4. **seekdb 侧**：`mysql -h 127.0.0.1 -P 2881 -u root` 后执行 `SHOW TABLES;` 与向量表行数查询的截图（证明元数据与向量同库一体化）；
5. 以上归档到 `evidence/`（命名建议 `A1.png`、`run-detail.png`、`seekdb-tables.png`…）并在本文件 §2 各表后补链接。

## 5. 判定基准（与题目 3.1 基础验收逐条对应）

| 验收条款 | 对应用例 | 通过标准 |
|---|---|---|
| 能运行、按预期给出回应 | A1、D1 | 任何输入都有台词 + 面板，不白屏不报错 |
| 核心互动链路完整（多轮输入/检索/变量读写） | A2/A3、C1、B2 | 检索命中影响让价；会话变量逐轮变化 |
| 技术有效性（seekdb/PowerContext 非摆设） | A3、C1 + §4.4 seekdb 查库截图 | 命中的文档片段与结算行为能对应 |
| 过程可观察（中间产物可查看） | §4.2/4.3 截图 | 运行详情可见节点链、召回内容、变量值 |
