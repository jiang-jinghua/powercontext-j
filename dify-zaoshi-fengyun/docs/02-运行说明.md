# 02 · 运行说明（对应提交材料 4.2）

从零到玩上《早市风云 · 老王菜摊》，预计 20~30 分钟。

## 1. 作品全貌

- **应用类型**：Dify Chatflow（advanced-chat），单应用，无第三方插件依赖。
- **拓扑**：`开始 → 早市情报检索（知识库）→ 摊主大脑（LLM）→ 结算台（代码节点）→ 局面写回（变量赋值）→ 老王开口（直接回复）`，共 6 节点。
- **外部依赖**：
  - OceanBase seekdb：同时作为 Dify 的**元数据库、向量库与全文索引**（一体化，替代 PG+Weaviate/ES）；
  - 一个 Chat 模型（OpenAI / DeepSeek / Qwen 等任意已在 Dify 配置好的模型）。

## 2. 运行环境

| 组件 | 要求 |
|---|---|
| Docker & Docker Compose | 任意较新版本 |
| Dify | **≥ 1.10.1**（该版本起官方支持 MySQL 元数据库，seekdb 才能作一体化后端） |
| seekdb | 随 Dify 官方 compose 的 `seekdb` profile 拉起，无需单独部署 |
| Git | 用于克隆 dify 仓库 |
| 模型 | 任一 Dify 支持的 Chat 模型供应商凭证 |

## 3. 第一步：部署 Dify × seekdb 一体化

按 OceanBase 官方教程《Dify x OceanBase seekdb 使用指南》执行（参数见 `deploy/seekdb.env.example`）：

```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
```

编辑 `.env`，将 seekdb 同时作为**元数据库 + 向量库**（官方推荐的一体化方案）：

```ini
DB_TYPE=mysql
DB_USERNAME=root
DB_HOST=seekdb
DB_PORT=2881
DB_DATABASE=test
VECTOR_STORE=oceanbase
OCEANBASE_VECTOR_HOST=seekdb
OCEANBASE_VECTOR_USER=root
COMPOSE_PROFILES=seekdb
```

> 不想动元数据库的话，退一档只用 seekdb 当向量库（保留 PG 元数据库）：
> `VECTOR_STORE=oceanbase`、`OCEANBASE_VECTOR_HOST=seekdb`、`OCEANBASE_VECTOR_USER=root`、
> `COMPOSE_PROFILES=seekdb,${DB_TYPE:-postgresql}`。本作品的 DSL 对两种方式都适用。

启动并确认：

```bash
docker compose up -d
docker ps          # 应看到 seekdb 与 docker-api-1、docker-web-1 等
```

打开 `http://localhost/apps` 注册管理员账号，进入 Dify 控制台。

**验证一体化**（可选但建议，作为运行证据之一）：用 MySQL 客户端连 `root@127.0.0.1:2881`，执行 `SHOW DATABASES;`——能看到 Dify 的元数据库（test）；导入知识库后再执行 `SHOW TABLES;`，能看到 Dify 的业务表与向量 embeddings 表都落在这一个 seekdb 实例里。

## 4. 第二步：配置模型

Dify 控制台 → 右上角头像 → **设置 → 模型供应商**，安装并配置任一 Chat 模型供应商（如 OpenAI、DeepSeek、通义千问）。记下模型名，后面导入 DSL 时选它。

## 5. 第三步：创建知识库「早市情报库」

1. 控制台 → **知识 → 创建知识库**，名称建议 `早市情报库`；
2. 上传 `seed/knowledge/` 下全部 6 个 markdown 文件：
   `01-今日行情.md`、`02-邻摊报价.md`、`03-黑话与挑菜.md`、`04-老王档案.md`、`05-砍价心理学.md`、`06-今日特价与暗号.md`；
3. 分段设置：通用分段，分段长度 **500** tokens，重叠 **50**；
4. 检索设置：选 **混合检索**（seekdb 同时提供向量与全文索引，混合检索落在同一引擎上，无需再单独部署 Elasticsearch）；
   - Rerank 没有配模型就选 **权重设置**，语义/关键词权重各 0.5；
5. 完成索引，**记下该知识库的 ID**（知识库设置页 URL 或 API 页面可见）。

## 6. 第四步：导入 DSL

1. 控制台 → **工作室 → 创建应用 → 导入 DSL**，上传 `dsl/zaoshi-fengyun.yml`（Dify DSL version 0.1.5，适用 Dify 1.x）；
2. 导入后打开编排页，**必做两处替换**（DSL 里的占位值在你的实例上必然不同）：
   - 节点「**摊主大脑（老王）**」：重新选择你配置好的 Chat 模型（默认占位为 `gpt-4o-mini`）；
   - 节点「**早市情报检索**」：在"知识库"里重新勾选第三步创建的 `早市情报库`（默认 dataset_id 是占位符）；
3. 其余节点无需改动；会话变量、开场白、结算台、变量赋值都已就绪；
4. 右上角 **发布 → 运行**，进入 WebApp。

## 7. 第五步：开玩（30 秒上手）

- 开场白会交代目标：12 元/斤 → 8 元/斤，6 轮；
- 想赢可以走"情报路线"：先跟老王聊两句，然后试试——
  - `李姐那边才 9 块 5，你这 12 块是金子做的？`（对比邻摊）
  - `听说你们进货 7 块 2，8 块你都不亏吧？`（套出底牌，一次顶三轮）
  - `来两把，给个实在价。`（老主顾暗号）
- 状态面板每轮更新现价、情绪条、轮次、招式统计与情报标记；
- 成交、掀摊、超时各有结局与成就；结束后再发一句即自动开新局。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 导入 DSL 后提示模型不可用 | 第 6 步第 2 条：在 LLM 节点重选模型即可，不影响导入 |
| 检索节点报 dataset 不存在 | 同上，重选知识库 |
| 老王台词不带 JSON/胡乱报价 | 结算台已做兜底（解析失败会用原文本并按"试探行情"结算），可在 Dify 运行详情里查看 LLM 原始输出定位提示词问题 |
| 检索结果为空 | 检查知识库是否完成索引；把检索设置的相似度阈值调低（如 0.2）；确认用混合检索 |
| `docker compose up` 拉镜像超时 | 给 Docker 配置 registry mirror 后重试（官方教程同款提示） |
| 想重置对局 | 直接新开会话；或结束后再发一句自动开新局 |
