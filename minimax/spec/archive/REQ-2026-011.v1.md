# REQ-2026-011 退款结算：类目排除分摊与尾差规则升级

- 规格编号：REQ-2026-011
- 版本：2026-11-07T20:00+08:00
- 状态：approved（待实现）
- 负责团队：交易结算组
- 关联工程：`settlement`（订单退款结算引擎）

## 1. 背景与目标

现有结算引擎把「优惠券金额 + 平台补贴」按订单行应付金额比例分摊到行，再以行实付金额作为退款依据。
业务侧在 2026-11 大促复盘中提出三个问题：

1. 赠品类目（`gift`）参与优惠分摊后，退货退款金额算不准：赠品行本身不该被优惠"摊薄"。
2. 尾差全部分给单行，导致个别订单出现某行多退 2~3 分，财务对账出现"行和 ≠ 单和"之外的二次核对成本。
3. 部分退货时若剩余商品实付为 0（整单单据已被优惠全额抵扣），运费却不退，产生客诉。

目标：在不改变既有整单口径（整单优惠总额、整单实付总额）的前提下，升级行级分摊规则与运费退还判定，
并补齐负金额校验与退款预览能力。

## 2. 范围

**In scope**

- 行级分摊：支持按类目排除；
- 尾差分配策略：由「单行吞噬尾差」改为「逐行 1 分轮转」；
- 运费退还判定；
- 分摊/退款负金额校验；
- 退款预览接口（不落状态）。

**Out of scope**

- 优惠券类型扩展（仅 `amount` / `percent`）；
- 跨订单合并退款、多次部分退款累积（当前一次调用对应一次退货动作）；
- 币种、汇率、税费。

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| 行应付（gross） | `unit_price_cents × qty`，单位分 |
| 待分摊额 | 优惠券优惠金额 + 平台补贴 |
| 行实付（paid） | `gross − 行分摊额` |
| 尾差 | 待分摊额减去各行向下取整分摊额后的余数（0 ≤ 尾差 < 行数） |
| 剩余实付 | 一次退货动作后，未退货行的实付金额合计 |

## 4. 规格条目

### SPEC-011-01 优惠分摊支持类目排除

- 优惠券定义新增可选字段 `excluded_categories: list[str]`（缺省 `[]`）。
- 分摊基数的构成：`gross > 0 且 category ∉ excluded_categories` 的行。
- 被排除行的分摊额恒为 `0`，其实付等于行应付；原份额按剩余行基数比例重新分摊。
- 整单口径不变：所有行分摊额之和仍等于待分摊额，整单实付 = `gross_total − 待分摊额`。
- 边界：若全部行都被排除（或剩余基数合计为 0），则待分摊额不向任何行分摊，不得抛异常；
  此时待分摊额记为「整单未分摊优惠」`unallocated_discount_cents`，整单实付仍按
  `paid_total = Σ行实付 + 运费 − 未分摊优惠` 计算，保证整单口径不变。
- 平台补贴与优惠券共用同一份 `excluded_categories`。

### SPEC-011-02 尾差按行轮转分配

- 每行先按 `Fraction(total × basis_i, Σbasis)` 向下取整。
- 尾差按「1 分/行」逐行分配；顺序为：该行分摊基数降序，基数相同则 `line_no` 升序。
- 单行尾差补偿上限为 1 分；尾差分配完毕后，各行分摊额之和必须精确等于待分摊额。
- 该策略替代基线版本的「尾差全部分给单行」，不得保留旧分支。

### SPEC-011-03 运费退还判定改为「剩余实付为 0」

- 退货后计算剩余实付 = 未退货行的 `paid` 合计。
- 剩余实付为 0 时退还全额运费；否则运费不退。
- 全部退货必然满足该条件，故与基线"整单全退才退运费"向后兼容。
- 运费退还额只计入 `shipping_refund_cents`，不摊入任何行。

### SPEC-011-04 负金额校验

- 分摊完成后，若存在 `paid < 0` 的行，抛 `NegativeAllocationError`，`error_code = E_NEG_ALLOC`，
  `detail` 至少包含 `order_id`、`line_no`、`paid_cents`。
- 退款明细计算完成后，若存在 `refund < 0`，抛 `NegativeRefundError`，`error_code = E_NEG_REFUND`。
- 两个异常均继承自 `RefundAmountError`（再继承 `SettlementError`）。
- **禁止**用 `max(0, x)` 静默夹断负值：负值代表数据结构或规则冲突，必须显式失败。

### SPEC-011-05 退款预览接口

- 新增 `engine.preview_refund(order, returned_line_nos) -> RefundResult`：内部完成结算 + 退款计算，
  调用方无需先持有 `Settlement`。
- 新增 `service.preview_refund_file(path, returned_line_nos) -> dict`。
- 新增 CLI 子命令：`python -m settlement.cli preview --order <path> --return 1,2`，输出 JSON 与 `refund` 子命令同构。
- 预览为只读操作：不写库、不改订单状态、不产生副作用。
- 预览结果必须与"先 `settle` 再 `refund`"的结果逐字段一致。

## 6. 错误码

| 错误码 | 类型 | 触发条件 |
| --- | --- | --- |
| `E_NEG_ALLOC` | `NegativeAllocationError` | 分摊后行实付为负 |
| `E_NEG_REFUND` | `NegativeRefundError` | 退款明细金额为负 |
| `E_ALLOCATION` | `AllocationError` | 分摊基数非法（全 0 / 负值） |
| `E_BAD_INPUT` | `ValidationError` | 订单输入非法 |
| `E_REFUND` | `RefundError` | 退货行非法 |

## 7. 兼容性与回归

- `tests/test_allocation.py`、`tests/test_engine.py`、`tests/test_service_cli.py` 为回归集合，
  实现前后必须全部通过，且不得修改断言。
- `engine.settle` / `engine.refund` / `service.*` / CLI `settle|refund` 的签名与输出结构保持不变（只增不改）。
- 新增字段仅在优惠券 JSON 中出现，旧订单 JSON 无需迁移。

## 8. 非目标与已知遗留

- 不支持按 SKU 级排除（仅类目）。
- 多次部分退货的累积对账不在本期范围，遗留于 backlog `BACKLOG-311`。
- 折扣券（`percent`）的排除类目语义与满减一致，但缺少专项测试，遗留于 `BACKLOG-312`。
